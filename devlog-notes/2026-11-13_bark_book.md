# 2026-11-13: the bark book (the barks with personalities in the game)

The writer's new `game/barks.csv` (CANON, rounds 133 to 135, 1039 rows) has the columns
`enemy,personality,situation,line,direction`. Before today the game did not read it: the lines were copied into the
code. The spec is `~/MEGA/glorified/dialogue/takes/barks_v2/GAME_NOTES.md`.

## What the game does now

1. `BarkBookSetup.Build` copies the writer's file to `Assets/_Game/Resources/Barks/barks.csv`. A player build has no
   access to the writers' folder. `DemoWorld.BuildAll` runs it too. After the writer changes the file:
   `tools/unity.sh exec GlorifiedBody.Editor.BarkBookSetup.Build`.
2. `Enemy/BarkBook.cs` reads the copy. It finds the rows by enemy, personality and situation. With no row for the
   personality, it uses the rows with an empty personality (the fallback).
3. `Enemy/BarkVoice.cs` is the voice of one person: its enemy (guard, soldier, armour, labworker, nurse, patient) and
   its personality, kept for the night. `EnemySpawn` gives it at the spawn.
4. One deck for each situation: the "plays first" row first, then the others at random, no repeat until all played.
   Only an armed person says a "plays first" row (all seven are the drop of the weapon in the cower).
5. A row with `PLACE: <thing>` plays only in a room whose title or objects name the thing.
6. The scripted rows (the Hold, W4, W8, G6, G10, G19, the coda) stay in the room builders. The builders read them
   from the writer's file (`BarkBookSetup.Scripted`) with the old line as the fallback. The demo scene keeps its
   baked lines until the next `DemoWorld.BuildAll`. The lines are the same.
